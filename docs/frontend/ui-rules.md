# Operational Warnings

Warnings should:
- guide
- inform
- prioritize

Warnings should NOT:
- overwhelm
- pollute
- feel alarming without reason

## Overload Visual Rules

Overload indicators should:
- use compact badges
- appear near the operational context they describe
- explain the pressure with concrete counts
- remain secondary to the campaign workflow

## Warning Badge Hierarchy

- normal: muted surface treatment
- watch: subtle warning treatment
- overloaded: error treatment used sparingly

## Operational Risk Visuals

Risk visuals should communicate:
- what is overloaded
- who or what is affected
- when the pressure happens

Risk visuals should avoid:
- decorative alerts
- excessive red surfaces
- vague urgency
- dashboard pollution

## Execution Warning Hierarchy

- healthy: positive but quiet
- warning: subtle timing or workflow attention
- at-risk: stronger visual emphasis, still contained
- blocked: high attention, used only for actual blockers
- overdue: high attention, tied to concrete dates

## Blocker Visuals

Blockers should:
- appear as compact cards
- include a concrete reason
- show simple severity
- sit near campaign workflow context

Blockers should NOT:
- look like tickets
- dominate the workspace
- create incident-management visual language

## Overdue Indicator Rules

Overdue indicators should:
- include timing language when possible
- be visible in dashboard and workspace
- stay derived from due date and active status

Overdue indicators should not become:
- countdown timers everywhere
- escalation banners
- automation triggers
