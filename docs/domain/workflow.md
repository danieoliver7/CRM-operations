# Workflow Domain

## Workflow Philosophy

Workflow exists to guide operational coordination.

The workflow should remain:
- simple
- contextual
- operational
- understandable

Avoid:
- workflow engines
- state machine complexity
- excessive branching
- enterprise orchestration

## Workflow Stages

briefing → copy → approval → development → qa → scheduled → sent → completed

## Workflow Behavior

Each stage provides:
- contextual actions
- contextual risks
- next operational steps
- operational guidance

## Workflow Rules

Workflow should:
- guide operations
- clarify responsibility
- expose blockers
- improve coordination

Workflow should NOT:
- become automation-heavy
- require complex orchestration
- become BPM software

## Contextual Actions

Actions depend on:
- current status
- operational context

Not every action changes status.
